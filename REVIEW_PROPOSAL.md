**Насколько обоснована гипотеза про перенос**

При подсчете смещений отдельно внутри каждого примера стандартное отклонение `dx` составляет около 25,5 пикселя; для движений с опущенным пером — около 1,59. Переходы после отрыва пера дают 99,56% суммы квадратов горизонтальных смещений. Большие возвраты, похожие на переход строки, дают 94,57% этой суммы. Критерий последних: предыдущая точка имеет `state=1`, `dx < -0,5 * ширина_образца`, `dy > 70`. Это эвристическая оценка, не ручная разметка всех переходов.

Текущая нормализация учитывает эти скачки вместе с маленькими движениями, образующими буквы. Генератор одновременно учится форме букв, положению следующей строки и большим перемещениям пера. Разделение задач должно упростить обучение; реальный прирост точности можно установить только сравнительным экспериментом. Само число 94,57% не доказывает причинность ошибок букв.

Исходная работа Graves, на которой основан проект, тоже использует отдельную рукописную строку как последовательность. Это поддерживает выбранное направление, но не гарантирует успех на данном наборе: [Generating Sequences With Recurrent Neural Networks, раздел 4](https://arxiv.org/html/1308.0850v5).

Удалять `\n` только из TXT нельзя: в координатах останется перенос. При `бу-\nлок` нельзя просто заменить перенос пробелом или убрать дефис только из подписи — соответствующий штрих останется в рисунке. Такие образцы надо либо сохранить как точно подписанные отдельные строки, либо вручную согласованно исправить траекторию и текст. Для начального набора полных слов удобнее использовать строки без переноса внутри слова.

**Предлагаемое устройство**

```text
Заданный текст
    ↓ проверка поддерживаемых символов
Однострочный генератор твоего почерка
    ↓ траектория + текст + границы слов + базовая линия
Проверка написанного текста и повтор неудачного фрагмента
    ↓ принятые слова/фрагменты
Вёрстка страницы: ширина, поля, интервалы, перенос целых слов
    ↓ JSON / SVG / PNG; при необходимости PDF
```

Начальная единица обучения — естественная строка или короткая фраза из нескольких слов. Предложение умеренной длины можно генерировать одной строкой. Очень длинное предложение лучше разбивать на фрагменты ограниченной длины: отсутствие переноса не устраняет накопление ошибок на тысячах последовательных шагов.

Для переноса уже сгенерированного текста нужны границы слов в траектории. Произвольный отрыв пера не равен границе слова: он бывает внутри букв, на точках, надстрочных элементах и знаках. Нельзя разрезать рисунок вертикальными полосами или просто сортировать точки по x. Нужно сохранить целые штрихи и принадлежность отложенных точек/дужек соответствующему слову. На первом этапе можно верстать целые короткие фрагменты; более гибкая верстка требует проверенных границ слов.

Для одного автора существующая модель уже имеет подходящий тип выхода — движения пера. Добавлять выбор автора или отдельную сложную модель стиля сейчас не требуется. Данные этого автора остаются единственным источником целевого почерка.

**Как проверить гипотезу без большого переобучения вслепую**

Сначала зафиксировать тестовый набор и критерии оценки. Текущую модель оценить как исходный уровень, насколько позволяет восстановить среду. Затем проверить способность модели свободно воспроизводить небольшой набор корректных записей: несколько слов и коротких фраз. Overfit-тест — диагностика работоспособности, не подтверждение обобщения на новые предложения.

Сравнить два новых запуска: A — исправленные многострочные пары без усечения; B — однострочные пары из тех же исходных записей. Использовать одинаковое разделение исходников, сопоставимый бюджет обработанных точек/обновлений, одинаковые настройки генерации, несколько фиксированных seed и отдельную оценку по длинам. Одинаковое число эпох недостаточно, поскольку после разделения строк меняется число примеров. Изменения плотности, stop head и режима teacher forcing вводить поэтапно, чтобы не приписать весь эффект переносу.

Для рабочего выбора модели считать точность свободной генерации основной метрикой. [src/generate_candidates.py:78](D:/Handwriting/src/generate_candidates.py:78) сейчас оценивает размеры рисунка, количество точек, отрывы и attention, но не буквы. Успешный `finished=true` тоже не подтверждает правильность текста. Хороший `val_loss` полезен для диагностики обучения, но недостаточен для этой цели.

Показать качество на новых предложениях, написанных строго без ошибок, важнее очередного снижения loss. Практический критерий приемки следует фиксировать численно: число проверенных предложений, доля точных, максимальное число попыток, число отказов и оценка сходства с автором. Ноль ошибок на конечном тесте не является математической гарантией для произвольного будущего текста.

В копии проекта были только `epoch_4`, `epoch_98`, `epoch_130`, `epoch_272`; сохраненных результатов свободной генерации и overfit-теста не было. `epoch_272` содержит train loss около −3,4044 и исторический best validation loss около −3,2712, но своей оценки validation в этом файле нет. Эпоха 4 имеет старый словарь 88 токенов, текущий словарь — 90. У 98 и 130/272 различаются статистики нормализации. Полного конфига обучения и хеша данных в сохранениях нет. Поэтому перечисленные дефекты доказаны для текущего кода/данных; точно назначить один из них единственной причиной прежнего неудачного запуска пока нельзя.

Первый практический этап: корректные однострочные пары, единая плотность точек, запрет усечения, фиксированная проверка новых предложений и диагностика конца текста. Вёрстку можно развивать отдельно, когда определен формат траекторий и границ слов.
